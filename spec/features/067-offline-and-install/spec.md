# 067 · Works offline, installs like an app

**Status:** in progress

## What it does

- **Offline.** After a first visit, `https://keireki-craft.eu/` opens and works with no connection:
  writing, the preview, every template, PDF/JPG/HTML/JSON export and PDF import. The CVs were always
  in the browser; now the app itself is too.
- **Install.** The browser offers to install it (Chrome and Edge on the desktop, Android; "Add to
  Home Screen" on iOS). Installed, it opens in its own window with the Keireki Craft icon.
- **Always the latest when online.** A new deploy is picked up on the next visit with a connection;
  there is no "new version" prompt and no stale page.

## Why

The mission promises "no connection required", and until now the page did not load without one.
Installing it gives the phone a home-screen icon and a full-screen window.

## Decisions

- **No new dependency.** The service worker is generated by a small Vite plugin of the project
  (`vite-plugin-pwa` would bring `workbox-build` and its tree, and the deploy runs every
  dependency's install scripts, spec 017).
- **What is downloaded ahead:** every file of the build (code, CSS, the PDF fonts, the country
  flags), about 11.5 MB once, in the background after the first visit, and again only for the files
  a deploy changes (their names carry a hash). Leaving the flags to be cached as shown was tried: offline,
  the phone field's flag then failed to load. Not precached: `og-image.png`, `robots.txt`, `sitemap.xml`.

- **Review fixes (2026-11-02).** The files of `public/` keep their names when they change (the
  favicon, the manifest, the icons): their content goes into the worker's version and they are
  fetched again at every install, or a new icon would never reach an installed app. An install
  stores nothing until every file has arrived with a success status: an error page is never kept
  as the offline page.

## Acceptance criteria

- [ ] After a first visit, with the network off, a reload opens the app, the sample CV opens and a
      PDF downloads.
- [ ] Online, a reload always gets the deployed `index.html` (network first), so a deploy shows at once.
- [ ] A file a deploy no longer has is dropped from the cache when the new service worker activates.
- [ ] `manifest.webmanifest`: name, short name, start URL and scope relative to the base, `standalone`,
      colours, the 192/512 icons and a maskable 512; Chromium reports the page installable.
- [ ] The service worker only answers GET requests to its own origin (ipwho.is and the AI assistants
      go to the network as before), and is not registered by `npm run dev`.
- [ ] The CSP is unchanged (`worker-src 'self'` and `default-src 'self'` already cover it).
- [ ] `npm test`, `npm run build`, `npm run qa:e2e` (with a new offline block) pass.

## Out of scope

- Push notifications, background sync, sharing a file into the app (Web Share Target).
- An "update available" prompt: not needed with network-first `index.html`.
